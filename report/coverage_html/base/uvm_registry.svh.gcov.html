     680              : // Group -- NODOCS -- Usage
     681              : //
     682              : // This section describes usage for the uvm_*_registry classes.
     683              : //
     684              : // The wrapper classes are used to register lightweight proxies of objects and
     685              : // components.
     686              : //
     687              : // To register a particular component type, you need only typedef a
     688              : // specialization of its proxy class, which is typically done inside the class.
     689              : //
     690              : // For example, to register a UVM component of type ~mycomp~
     691              : //
     692              : //|  class mycomp extends uvm_component;
     693              : //|    typedef uvm_component_registry #(mycomp,"mycomp") type_id;
     694              : //|  endclass
     695              : //
     696              : // However, because of differences between simulators, it is necessary to use a
     697              : // macro to ensure vendor interoperability with factory registration. To
     698              : // register a UVM component of type ~mycomp~ in a vendor-independent way, you
     699              : // would write instead:
     700              : //
     701              : //|  class mycomp extends uvm_component;
     702              : //|    `uvm_component_utils(mycomp)
     703              : //|    ...
     704              : //|  endclass
     705              : //
     706              : // The <`uvm_component_utils> macro is for non-parameterized classes. In this
     707              : // example, the typedef underlying the macro specifies the ~Tname~
     708              : // parameter as "mycomp", and ~mycomp~'s get_type_name() is defined to return
     709              : // the same. With ~Tname~ defined, you can use the factory's name-based methods to
     710              : // set overrides and create objects and components of non-parameterized types.
     711              : //
     712              : // For parameterized types, the type name changes with each specialization, so
     713              : // you cannot specify a ~Tname~ inside a parameterized class and get the behavior
     714              : // you want; the same type name string would be registered for all
     715              : // specializations of the class! (The factory would produce warnings for each
     716              : // specialization beyond the first.) To avoid the warnings and simulator
     717              : // interoperability issues with parameterized classes, you must register
     718              : // parameterized classes with a different macro.
     719              : //
     720              : // For example, to register a UVM component of type driver #(T), you
     721              : // would write:
     722              : //
     723              : //|  class driver #(type T=int) extends uvm_component;
     724              : //|    `uvm_component_param_utils(driver #(T))
     725              : //|    ...
     726              : //|  endclass
     727              : //
     728              : // The <`uvm_component_param_utils> and <`uvm_object_param_utils> macros are used
     729              : // to register parameterized classes with the factory. Unlike the non-param
     730              : // versions, these macros do not specify the ~Tname~ parameter in the underlying
     731              : // uvm_component_registry typedef, and they do not define the get_type_name
     732              : // method for the user class. Consequently, you will not be able to use the
     733              : // factory's name-based methods for parameterized classes.
     734              : //
     735              : // The primary purpose for adding the factory's type-based methods was to
     736              : // accommodate registration of parameterized types and eliminate the many sources
     737              : // of errors associated with string-based factory usage. Thus, use of name-based
     738              : // lookup in <uvm_factory> is no longer recommended.
